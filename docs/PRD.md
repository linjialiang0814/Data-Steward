# 产品需求文档（PRD）

> 产品代号：待定（文档中简称“智能管家”）  
> 版本：APP Demo Release Candidate v0.6  
> 更新日期：2026-08-06  
> 目标平台：Windows 10/11 + Android 10+ 手机/Pad

> S6-G 交付注记：当前实证主体为 Windows PC + 一台华为 Android 手机。已实现双设备目录、时间/文件名聚类、PC TXT/MD/DOCX/PPTX/文本 PDF 受控理解、Android JPG/PNG 端侧 OCR、Hermes 多步只读资料包与主动 Action Card，以及用户确认后的 PC 分组整理、Markdown 导出和安全撤销。Pad、多端写入 Saga、录音转写、扫描 PDF OCR 和正式办公系统写入仍是产品目标，不代表已交付。

## 1. 产品定义

智能管家是一套本地优先的个人多设备数据中枢与共享 Agent 工作空间。它不要求用户先把所有文件搬到同一云盘，而是在用户授权后建立跨设备统一目录。PC、手机和 Pad 显示同一会话；用户可从任意端发起跨设备检索、汇总和整理，Agent 将意图拆成目标明确的设备步骤，返回可核验回执，并从已确认行为中形成可解释、可遗忘的跨会话记忆。

一句话价值：

> 在任意设备说出目标，所有设备协同执行、同步反馈，并逐渐学会用户认可的整理方式。

## 2. 用户与主任务

### 2.1 核心用户画像

- 同时使用 Windows PC、Android 手机，可能还使用 Android Pad；
- 每周产生大量课件、需求文档、截图、照片、录音、录屏和项目文件；
- 记得“什么时候、关于什么、在哪里见过”，但经常忘记文件名；
- 愿意让 AI 帮助整理，但不接受黑盒扫描、静默上传或擅自移动文件。

### 2.2 MVP 主场景：三端训练营 Agent 工作空间

数据被有意分散在三端：

- 手机：导师语音、白板照片、群聊下载的需求截图、灵感笔记；
- Pad：评审反馈、批注文档、展示素材和阅读笔记；
- PC：README、架构文档、原型截图、测试报告、演示视频；
- 手机意图：“看下 PC 桌面有几个图片文件，找出与数据同步有关的文件，先给我一个整理方案。”
- PC 意图：“汇总所有设备关于多设备管家的资料，按答辩结构整理，并把今天的交互记录写入手机和 Pad。”

系统应完成：三端会话实时同步 → Agent 拆分带目标设备的计划 → PC/手机/Pad 准确执行并返回回执 → 全设备资料汇总与来源引用 → 真实归档/记录写入的预览、确认和撤销 → 自动识别整理模式 → 在新会话、另一设备引用已批准的规则。

该场景既属于 README 的学生/项目资料管理，也与本项目本身直接相关，便于评委验证真实性。

## 3. 核心体验原则

1. **先找到，再行动**：检索与证据是所有 Agent 动作的前置条件。
2. **三端同一事实**：消息、计划、确认、步骤状态和结果必须在断线回放后最终一致。
3. **来源与目标始终可见**：结果显示来源设备；计划显示实际执行设备、授权范围和命中原因。
4. **AI 规划，代码裁决**：模型生成候选计划，能力路由器选定设备，策略引擎决定是否允许执行。
5. **执行必须有回执**：不能用 Agent 的自然语言“已完成”替代文件状态、hash 和设备回执。
6. **默认不破坏原文件**：优先标签、关系和虚拟集合；Showcase 所需的物理变更需单独确认并可撤销。
7. **离线不装作在线**：缓存可以搜索，多设备任务允许部分结果，但不得伪造整体成功。
8. **自主发现、用户控制**：系统自动发现习惯；长期规则可解释、可编辑、可停用、可删除。
9. **核心路径不依赖公网**：局域网、索引、会话同步和已批准操作应可离线运行。

## 4. 核心用户旅程

| 阶段 | 用户行为 | 系统行为 | 成功信号 |
|---|---|---|---|
| 1. 建立信任 | PC 显示二维码，手机/Pad 扫码并核对短码 | 建立三台设备身份，声明能力和授权范围 | 三端均可撤销，30 秒内单台配对 |
| 2. 进入共享会话 | 任意端打开 Agent 对话 | 回放会话并订阅消息/计划事件 | 三端顺序和状态一致 |
| 3. 远程访问 | 手机询问 PC 桌面图片数量/主题文件 | Agent 解析目标 PC、拆解并只读执行 | 三端同步看到正确数量和来源 |
| 4. 整理计划 | 手机请求“整理 PC 桌面” | 输出文件级 Dry-run、风险和目标设备 | 计划可读、无越权对象 |
| 5. 确认执行 | 用户在已认证端确认 | PC 真实移动/重命名并返回回执/逆操作 | 文件状态一致，可一键撤销 |
| 6. 全端汇总 | PC 请求汇总所有设备资料 | 三设备分支并行检索，汇合为带来源任务包 | 部分离线时状态真实 |
| 7. 跨端分发 | PC 请求写入今日交互记录 | 手机/Pad 分别写入授权记录目录 | 两端返回路径、大小、hash |
| 8. 习惯与记忆 | 用户多次纠正分类并批准建议 | 自动发现规则，跨会话按相关性检索 | 新会话/另一端能引用来源 |
| 9. 追溯/遗忘 | 查看活动/记忆并撤销、停用或删除 | 更新三端状态，后续计划不再使用 | 操作链完整、遗忘立即生效 |

## 5. MVP 功能需求与验收标准

### 5.1 P0 功能

| ID | 功能 | 验收标准 |
|---|---|---|
| FR-001 | 三端配对 | PC、手机、Pad 通过 QR + 短码分别配对；未批准设备无法接入；支持撤销与能力变更重配 |
| FR-002 | 三端可视化共享会话 | 同一会话的消息、来源端、计划、确认、进度和结果实时同步；断线按序回放且不重复 |
| FR-003 | 授权目录管理 | 使用系统选择器；可查看/移除授权；拒绝访问授权根目录之外的真实路径 |
| FR-004 | 增量资产索引 | 支持新增、修改、删除事件；重启后续跑；单个失败不阻塞全量任务 |
| FR-005 | 设备能力与状态 | 声明 `fs.read/fs.write/note.write` 等能力；展示在线、最后同步、索引进度和错误摘要 |
| FR-006 | 跨端混合检索 | 一次查询返回 PC/手机/Pad 结果；支持文本、设备、类型、时间过滤；P0 覆盖常见 JPG/PNG 中文截图 OCR；结果带来源依据 |
| FR-007 | Agent 计划与设备路由 | 计划步骤含依赖、目标设备、工具、前置条件和风险；显式目标不得路由到错误设备 |
| FR-008 | 可核验执行回执 | 每步返回实际设备、授权根、revision/hash、影响数和状态；自然语言不得替代回执 |
| FR-009 | 手机操作 PC 文件 | 手机能统计/查找 PC 授权 Desktop 文件；整理请求必须先 Dry-run 再确认执行 |
| FR-010 | 全设备汇总 | 并行检索三端并生成带来源任务包；离线时返回缓存/部分完成，不伪造成功 |
| FR-011 | 跨端记录写入 | PC 可把当日会话导出并分别写入手机/Pad 的授权或 App 记录目录，返回独立回执 |
| FR-012 | 虚拟集合与真实归档 | 默认虚拟集合；授权目录内的移动/重命名支持预览、确认、版本校验和撤销 |
| FR-013 | 审计与 Saga | 多设备任务展示每步 `pending/running/succeeded/failed`；整体支持 partial；所有写动作可追溯 |
| FR-014 | 习惯识别 | 从已确认/纠正事件自主提出至少一类分类规则，显示证据、置信度和适用范围 |
| FR-015 | 跨会话记忆 | 批准规则可从新会话、另一设备检索使用；记忆有来源并支持修改、停用、删除和遗忘验证 |
| FR-016 | 网络恢复 | 临时错误有界退避；永久错误不重试；稳定窗口后补会话/变更事件且不重复执行 |
| FR-017 | 确定性降级 | LLM 不可用时仍可同步会话、关键词检索、查看任务包和执行已确认的安全计划 |

### 5.2 P1 增强

- 批量/版面增强 OCR 与更多课件/文档结构抽取；

## 7. Agent 行为合同

### 7.1 允许调用的领域工具

- `search_assets(query, filters)`：只读检索；
- `count_assets(device_id, root_id, filters)`：在明确设备/授权根统计文件；
- `get_asset_context(asset_ids, fields)`：在授权范围读取最小必要片段；
- `summarize_assets(asset_ids, template)`：生成带设备/文件来源的结构化汇总；
- `get_device_status(device_ids)`：读取设备能力、在线与索引新鲜度；
- `propose_collection(goal, asset_ids, grouping)`：生成候选集合，不执行；
- `propose_archive(device_id, root_id, asset_ids, strategy)`：生成文件级归档 Dry-run；
- `validate_plan(plan_id)`：由策略引擎返回风险和冲突；
- `apply_plan(plan_id, approval_token)`：仅执行已批准且未过期的计划；
- `undo_action(action_id, approval_token)`：执行受支持的逆操作；
- `export_conversation(session_id, date, format)`：生成带来源的会话记录；
- `write_note(device_id, root_id, name, content_hash)`：写入手机/Pad 授权记录目录并返回回执；
- `propose_rule(evidence_ids)`：生成可解释规则建议；
- `save_rule(proposal_id, approval_token)`：保存用户明确接受的规则。

### 7.2 风险等级

| 等级 | 示例 | 策略 |
|---|---|---|
| R0 只读 | 搜索元数据、查看设备状态 | 授权范围内自动执行 |
| R1 非破坏写 | 新建标签/虚拟集合/派生清单 | 展示结果，可按用户设置简化确认 |
| R2 文件变更 | 复制、移动、重命名、批量生成 | 必须 Dry-run + 显式确认 + 版本前置校验 |
| R3 高风险外部影响 | 删除、覆盖、上传、分享、任意程序/脚本 | MVP 禁止或永远强确认；优先不实现 |

模型永远不能提升自身权限，文档中的文字永远不能被当作系统指令或授权。

### 7.3 学习与记忆合同

- `Working Memory`：当前会话目标、证据、计划与设备状态；随会话管理；
- `Conversation Memory`：共享消息、摘要和对应事件序号范围；支持三端回放/会话检索；
- `Episodic Memory`：已完成任务、用户修改/拒绝和执行结果；按相关性检索；
- `Preference Memory`：用户批准的分类、命名和分发规则；跨会话版本化；
- `Procedural Memory`：受控工具组合与任务模板；不能自行绕过策略新增任意能力。

长期记忆必须包含 `source_event_ids、scope、confidence、reason、status、version`。系统可自主生成候选记忆，但改变后续写操作的规则只有用户批准后生效。Agent 使用记忆时要在 UI 展示“使用了哪条记忆及其来源”；用户停用/删除后，下一轮不得继续使用。

## 8. 非功能需求

### 8.1 性能

- 10,000 条资产元数据规模下，普通检索 P50 < 500 ms、P95 < 1.5 s（不含 LLM）；
- 三端在线消息/计划事件同步 P95 < 500 ms；
- 单端新增文件到索引可见 P95 < 3 s（设备在线、解析器支持时）；
- 首次索引提供实时进度，UI 不阻塞；
- 大文件采用流式/分块传输，不将整文件常驻内存。

### 8.2 可靠性

- 传输与写动作使用请求 ID/幂等键；重放不造成重复副作用；
- Hub 为共享会话分配单调递增 `conversation_seq`；客户端用
  `last_conversation_seq` 补缺口；
- MVP 同一会话一次只执行一个 Agent Run，新的用户消息排队或显式取消，避免计划交错；
- 设备维护变更序号和 checkpoint，断线后从断点恢复；
- 永久错误不重试；临时错误使用指数退避 + full jitter + 上限；
- 检测到网络变化后等待 3～5 秒稳定窗口和连续健康检查再同步；
- 破坏性计划不在长时间离线后静默执行，恢复时重新校验并按需重新确认；
- 进程重启后从持久化 outbox/action log 恢复状态。
- 跨设备计划采用 Saga 汇总 `succeeded/partial/failed/cancelled`，任何部分失败不得显示整体成功。

### 8.3 隐私与安全

- 默认只处理用户显式授权目录，支持撤销；
- 原文件默认留在源设备，中心只保留必要索引和用户允许的派生信息；
- 云模型调用有总开关与逐次可见提示，只发送最小必要、可脱敏的片段；
- 密钥进入系统安全存储，日志禁止记录原文、访问令牌和完整敏感路径；
- 路径规范化并解析符号链接后再次校验授权边界；
- 每个写动作记录计划、风险、确认、文件版本、结果和撤销状态。
- 长期记忆不保存完整原文、访问令牌或未经授权敏感内容；支持导出和遗忘。

### 8.4 可观测与可测

- 一个 `trace_id` 贯穿意图、检索、计划、策略、确认、设备执行和结果；
- 记录会话同步延迟/缺口、设备路由、搜索命中、同步队列、连接/重试、Agent 接受/修改/拒绝率、规则命中和策略拦截；
- 提供固定合成数据集、黄金查询集、危险指令集与故障注入开关；
- 指标必须标注测试硬件、数据规模、文件类型分布和测试版本。

## 10. Demo 完成定义

一个版本只有同时满足以下条件才算“完成”，而不是“功能代码写完”：

- Windows、真实 Android 手机与 Android Pad 完成同一条端到端旅程；无 Pad 硬件时模拟器必须明确标注且不冒充真机；
- 所有 P0 验收项有测试或录屏证据；
- 全新环境有可执行的安装/启动说明；
- 不依赖开发者手工改数据库或临时复制文件；
